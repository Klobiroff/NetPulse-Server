# NetPulse

NetPulse помогает строить сетевые игры на Unity. Решение состоит из двух частей: сервера на .NET 10, который вы размещаете сами, и Unity-пакета `com.netpulse.unity`, рассчитанного на Unity от 2021.3 до 6000.x. Если вы работали с Photon PUN, модель вам знакома: игроки подключаются, попадают в лобби, создают комнаты и входят в них, обмениваются свойствами комнаты и игрока, вызывают RPC и синхронизируют сетевые объекты.

Обе части сейчас имеют версию 0.3.

## Что внутри

Сервер:

- Лобби и подбор комнат: именованные комнаты, случайный вход с фильтром по свойствам, список комнат с дельтами в реальном времени.
- Каждая комната работает на своём асинхронном файбере, поэтому медленная комната не задерживает ни другие комнаты, ни лобби, ни сетевой поток.
- Кэш событий для опоздавших игроков, время жизни игрока и пустой комнаты для повторного входа.
- Проверка владения сетевыми объектами на сервере: клиент не может двигать, удалять или забирать чужие объекты.
- Защита от флуда для каждого пира, проверка AppId и версии протокола, необязательная собственная аутентификация.
- Плагины на C#: хуки входа, событий, изменения свойств и закрытия комнаты, таймеры, HTTP-запросы, фоновая работа и горячая перезагрузка.
- Метрики через `System.Diagnostics.Metrics` и небольшой набор консольных команд.

Unity:

- Асинхронный API (`await Pulse.Connect()`, `await Pulse.JoinOrCreateRoom(...)`) с альтернативами на колбэках и корутинах.
- RPC, `SyncVar<T>`, типизированные сообщения и типизированные ключи свойств комнаты и игрока. Код для них создаёт генератор исходного кода, а ошибки ловят анализаторы.
- Сетевые объекты с владением, сценовые объекты, сетевые сцены, сетевой тик и офлайн-режим.
- Инструменты редактора: ассет настроек, окно Hub с профайлером трафика и генерация link.xml для IL2CPP.

## Сравнение с PUN

Понятия совпадают в основном один в один, поэтому большая часть PUN-кода переносится переименованием. Различия в том, где работает сервер и кто проверяет правила. NetPulse размещается у вас: вы запускаете серверный бинарник на своей машине и пишете серверную логику плагинами на C#, а не пользуетесь облачным сервисом. Владение объектами проверяет сам сервер, а Unity API построен на `async`/`await` и сгенерированном коде вместо вызовов по строковым именам. Конкретные замены перечислены на странице [Переход с PUN](migrating-from-pun.md).
