# Горячая перезагрузка

Если `NetPulse:Plugins:HotReload` включён (по умолчанию так и есть), плагин можно заменить, не останавливая сервер. Игроки остаются подключёнными, а работающие комнаты не прерываются.

## Что происходит при изменении файлов

1. Сервер следит за папкой плагинов, включая подпапки. Любое изменение внутри папки плагина запускает для неё таймер на полсекунды. Новые изменения перезапускают таймер, поэтому копирование нескольких файлов даёт одну перезагрузку.
2. Сервер загружает `plugin.json` и сборку из этой папки в новый изолированный контекст загрузки. Файлы читаются в память, поэтому ничего не блокируется и вы можете перезаписывать их снова в любой момент.
3. Если загрузка удалась, новая версия занимает место плагина под тем же именем. Комнаты, созданные с этого момента, используют её.
4. Комнаты, которые уже работают с плагином, остаются на старой версии, пока не закроются. Когда закрывается последняя из них, старая версия выгружается.

В логе появляется `Loaded plugin <name> v<N> from <folder>`. Число берётся из общего счётчика загрузок сервера, поэтому оно растёт при каждой загрузке любого плагина.

Если загрузка не удалась, например dll скопирована не полностью или манифест некорректен, сервер пишет `Failed to load plugin from <folder>; keeping previous version if any`, и прежняя версия остаётся активной. Следующее изменение файлов запустит новую попытку.

Другие случаи:

- Новая папка с корректным манифестом загружается как новый плагин.
- Удаление папки плагина выгружает плагин. Работающие комнаты доживают на нём, а комнаты, которые запросят его позже, получат `PluginNotFound`.
- Если плагин указан в `NetPulse:Plugins:Auth`, успешная перезагрузка заменяет плагин аутентификации для новых входов.

## Ручная перезагрузка

Консольная команда принудительно перезагружает одну папку, даже когда `HotReload` выключен:

```text
reload GreeterPlugin
```

Она принимает имя папки, печатает `reloaded` или `reload failed` и пишет подробности в лог. Командой `plugins` можно проверить, какие плагины загружены и сколько комнат использует каждый.

При `HotReload`, равном `false`, сервер загружает плагины только при запуске плюс то, что вы перезагрузите вручную.

## О чём помнить

- Состояние живёт в объекте плагина комнаты. Комната никогда не переключается между версиями, так что её поля остаются согласованными. Новая комната начинает с чистого состояния.
- У каждой версии своя копия статических полей. Не используйте статику для обмена данными между комнатами, которые могут работать на разных версиях.
- Настройки берутся из `appsettings.json` и переменных окружения при запуске сервера. Чтобы их изменить, нужен перезапуск. При перезагрузке плагина фабрика получает те же настройки, что и раньше.
- Всё, что переживает комнату и ссылается на код плагина, может удерживать старую версию в памяти: запущенный вами поток, неосвобождённый таймер, статическая подписка на событие. Останавливайте свои потоки в `DisposeAsync` или `OnCloseRoomAsync`.
- Изменение контракта между плагином и клиентами, например нового значения кода события, по-разному действует на комнаты в зависимости от версии. Если смешение версий запутает клиентов, выкатывайте такие изменения с перезапуском.
- Общие сборки (`NetPulse.Plugins`, `NetPulse.Common`) приходят с сервера и горячей перезагрузке не подлежат. Для обновления SDK нужен перезапуск сервера и пересборка плагина.

## Освобождение ресурсов

Когда комната закрывается, сервер вызывает `DisposeAsync` у её объекта плагина. Переопределите метод, если плагин держит ресурсы.

```csharp
public override ValueTask DisposeAsync()
{
    _client.Dispose();
    return default;
}
```

При остановке сервера то же происходит для каждой комнаты, а затем выгружаются все контексты загрузки.
