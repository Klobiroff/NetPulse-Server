# Обзор плагинов

Плагин представляет собой библиотеку классов .NET, которую сервер загружает из папки и запускает внутри ваших комнат. Он нужен там, где серверу приходится принимать решение, которое нельзя доверить клиентам: проверить событие, вести авторитетный счёт, сверить игрока со списком допущенных перед входом или вести матч по таймеру.

## Что умеет плагин

- Перехватывать происходящее в комнате через хуки: создание, вход, выход, событие, изменение свойств, передачу владения и закрытие комнаты. Хук может пропустить действие, изменить его, тихо отбросить или отклонить. См. [Хуки](hooks.md).
- Действовать на комнату через API хоста: рассылать события, менять свойства комнаты и игроков, выгонять игроков, закрывать комнату. См. [API хоста](host-api.md).
- Запускать таймеры, обращаться к HTTP-сервисам и выполнять фоновую работу. См. [Таймеры, HTTP и фоновая работа](timers-http-background.md).
- Аутентифицировать клиентов раньше, чем они попадут в комнату. См. [Аутентификация](authentication.md).

## Составные части

| Часть | Роль |
|---|---|
| `plugin.json` | Манифест в папке плагина: имя, сборка, тип фабрики и необязательный тип аутентификации. |
| `IPluginFactory` | Создаётся один раз для каждой загруженной версии плагина. Сервер вызывает `CreateAsync` каждый раз, когда создаётся комната, использующая плагин. |
| `RoomPlugin` | Объект, который получает хуки. У каждой комнаты свой экземпляр, поэтому поля плагина хранят состояние комнаты. Наследуйтесь от этого базового класса и переопределяйте только нужные хуки. |
| `IPluginHost` | Средство, с помощью которого плагин действует на свою комнату. Базовый класс показывает его как `Host`. |

Комната выбирает плагин по имени через `RoomOptions.Plugin`. Комнаты без имени используют `NetPulse:Plugins:Default`, а если и он пуст, работают без плагина.

## Комната делает одно дело за раз {#the-room-runs-one-thing-at-a-time}

У каждой комнаты есть своя очередь и один обработчик, который называется файбером. Файбер берёт из очереди один элемент (сообщение клиента, вход, выход, запуск таймера), выполняет его до конца вместе со всеми `await` внутри и только потом берёт следующий. У лобби свой файбер, у каждой другой комнаты тоже.

Из этой модели следует четыре вещи:

- Код одной комнаты никогда не выполняется параллельно с другим кодом этой же комнаты. Блокировки вокруг состояния комнаты, полей плагина и `Host.RoomProperties` не нужны.
- После `await` внутри хука вы снова на файбере комнаты, так что работать с состоянием комнаты по-прежнему безопасно. Не используйте `ConfigureAwait(false)` и `Task.Run` в коде, который трогает состояние комнаты.
- Медленный хук тормозит только свою комнату. Пока хук ждёт базу данных, комната больше ничего не обрабатывает, потому что порядок сообщений важнее задержки. Остальные комнаты, лобби и сетевой поток продолжают работать. Хук, который никогда не завершается, обрывается через `HookTimeoutMs`.
- Колбэки таймеров и другие продолжения не являются элементами очереди. Они выполняются на том же файбере, но могут сработать, пока хук приостановлен на `await`. Два фрагмента кода никогда не работают в один и тот же момент, но могут чередоваться в точках ожидания.

Работу, результат которой не влияет на исход вызова, например аналитику или сохранение результата матча, выносите в `Host.RunInBackground`, чтобы комната её не ждала.

## Версии плагина и горячая перезагрузка

Сервер загружает плагин в собственный выгружаемый контекст загрузки. Когда вы перезаписываете файлы, новые комнаты используют новую версию, а работающие доживают на старой. См. [Горячая перезагрузка](hot-reload.md).

## Примеры плагинов

В репозитории в папке `plugins/` лежат два плагина:

- `NetPulse.Plugins.Sample` ведёт авторитетный счёт каждого игрока, раз в секунду рассылает тик таймера и отклоняет один код события. Он показывает хуки, фабрику с настройками и таймер.
- `NetPulse.Plugins.AuthSample` реализует `IAuthPlugin` в режимах HMAC-токена и HTTP. См. [Аутентификация](authentication.md).
