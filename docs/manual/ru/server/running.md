# Запуск сервера

Сервер представляет собой консольное приложение на .NET 10, построенное на generic host. Он слушает один UDP-порт, загружает плагины из папки рядом с бинарником и читает консольные команды из стандартного ввода.

## Запуск из исходников

```bash
dotnet build
dotnet run --project src/NetPulse.Server
```

Сборка решения копирует пример плагина (и плагин AuthSample) в `src/NetPulse.Server/bin/<Config>/net10.0/plugins/`. Именно там сервер ищет плагины.

## Запуск опубликованной сборки

После [публикации](deployment.md) запустите исполняемый файл или dll:

```bash
./NetPulse.Server
dotnet NetPulse.Server.dll
```

В Windows исполняемый файл называется `NetPulse.Server.exe`.

## Вывод при старте

Обычный запуск печатает по строке на каждый загруженный плагин, порт и список консольных команд:

```text
info: NetPulse.Server.Plugins.PluginManager[0] Loaded plugin NetPulse.Plugins.Sample v1 from NetPulse.Plugins.Sample
info: NetPulse.Server.Networking.NetPulseServer[0] NetPulse server listening on UDP 5055
info: NetPulse.Server.Commands.ConsoleCommandService[0] Console commands: stats, plugins, reload <folder>, quit
```

Число `v1` после имени плагина берётся из счётчика, который сервер увеличивает при каждой загрузке плагина, так что второй загруженный плагин получит `v2`. Версия самого плагина здесь не отображается.

## Изменение настроек {#changing-settings}

Сервер читает `appsettings.json`, а затем переопределяет значения переменными окружения и аргументами командной строки. Побеждает более поздний источник.

=== "appsettings.json"

    ```json
    {
      "NetPulse": {
        "Port": 6000,
        "AppId": "my-game"
      }
    }
    ```

=== "Переменная окружения"

    ```bash
    NetPulse__Port=6000 ./NetPulse.Server
    ```

=== "Командная строка"

    ```bash
    ./NetPulse.Server --NetPulse:Port=6000
    ```

Если в ключе есть двоеточие, в имени переменной окружения пишите двойное подчёркивание (`NetPulse__Plugins__Auth`). Все параметры перечислены в разделе [Конфигурация](configuration.md).

!!! warning "appsettings.json берётся из рабочей папки"
    Хост ищет `appsettings.json` в текущей рабочей папке, а не рядом с бинарником. Если вы запускаете сервер из другой папки, например из менеджера служб, задайте рабочую папку с вашим `appsettings.json` или используйте переменные окружения. С папкой плагинов иначе: относительный путь `NetPulse:Plugins:Directory` отсчитывается от папки с бинарником сервера.

Значение `NetPulse:Port` равное `0` выбирает случайный свободный порт. Какой именно, покажет строка лога `listening on UDP <port>`.

## Остановка сервера {#stopping-the-server}

Нажмите Ctrl+C, введите `quit` (или `exit`) в консоли либо отправьте SIGTERM. Дальше сервер делает следующее:

1. Перестаёт принимать новые подключения.
2. Закрывает все комнаты, вызывая для каждой `OnBeforeCloseRoomAsync` и `OnCloseRoomAsync`, в пределах `NetPulse:ShutdownTimeoutMs` (по умолчанию 10 секунд). Если комнаты не успели, сервер пишет `Not all rooms closed within ...` и продолжает остановку.
3. Останавливает сетевой менеджер, освобождает плагины и выгружает их контексты загрузки.

Клиенты в комнате перед отключением получают событие `ErrorInfo` с кодом `RoomClosed`.

## Когда сервер отказывается запускаться

Процесс завершается с необработанным исключением в двух случаях:

- UDP-порт уже занят: `Could not bind UDP port 5055`.
- `NetPulse:Plugins:Auth` указывает на плагин, который не установлен, не загрузился или не создался: `Plugins:Auth is set to '...' but no authentication plugin could be loaded; refusing to start without authentication`.

Второй случай сделан намеренно. Сервер, настроенный на аутентификацию, никогда не переходит к приёму всех подряд. См. [Безопасность](security.md).

## Консольный ввод

Консоль читает команды, пока `NetPulse:EnableConsole` равен `true`. Если стандартный ввод закрыт или перенаправлен из `/dev/null`, консольная служба просто завершается, а сервер продолжает работать. Для служб и контейнеров отключите параметр. Команды описаны в разделе [Эксплуатация](operations.md).

## Проверка тестовым клиентом {#try-it-with-the-test-client}

В репозитории есть клиент-бот, `tools/NetPulse.TestClient`:

```bash
dotnet run --project tools/NetPulse.TestClient -- --bots 2 --room test --seconds 6
```

| Флаг | По умолчанию | Значение |
|---|---|---|
| `--host` | `127.0.0.1` | Адрес сервера |
| `--port` | `5055` | UDP-порт сервера |
| `--bots` | `2` | Количество ботов |
| `--room` | `test` | Имя комнаты |
| `--plugin` | `NetPulse.Plugins.Sample` | Плагин, который запрашивается для комнаты; пустая строка означает «без плагина» |
| `--seconds` | `6` | Сколько боты обмениваются событиями |
| `--app-id` | нет | AppId, отправляемый серверу |
| `--key` | `NetPulse` | Ключ подключения LiteNetLib |
| `--token` | нет | Токен аутентификации |
| `--make-token`, `--secret`, `--user`, `--nick`, `--ttl-minutes` | | Напечатать токен AuthSample вместо запуска ботов, см. [Аутентификация](../plugins/authentication.md) |

Код выхода 0 означает, что боты увидели события друг друга, тики таймера и серверный счёт от примера плагина, а пример плагина отклонил событие 99. Последняя проверка выполняется всегда, поэтому с `--plugin ""` или с любым плагином, кроме примера, клиент сообщает `FAILED`, даже когда сервер исправен. В таком случае смотрите на строки `joined`: они показывают, что подключение, аутентификация и вход прошли.
