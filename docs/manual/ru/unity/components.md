# Компоненты

Три готовых компонента покрывают типичные случаи: `NetworkTransform`, `NetworkRigidbody` и `NetworkAnimator`. Каждый из них `NetworkBehaviour`, поэтому на корне GameObject также нужен `NetworkObject`. Их можно найти в `Add Component > NetPulse`. Все они отправляют состояние от владельца и применяют его у остальных, используя `OnSerialize` ([синхронизация состояния](state-sync.md)).

## NetworkTransform

Синхронизирует позицию, поворот и масштаб и сглаживает движение у удалённых клиентов интерполяцией. На объекте допустим только один такой компонент.

Синхронизация:

| Опция | По умолчанию | Значение |
|---|---|---|
| Sync Position | вкл. | Отправлять и применять позицию |
| Sync Rotation | вкл. | Отправлять и применять поворот |
| Sync Scale | выкл. | Отправлять и применять локальный масштаб |
| Use Local Space | вкл. | Использовать `localPosition` и `localRotation`. Выключите, чтобы синхронизировать мировые значения. Для корневого объекта они совпадают. |
| Reliable | выкл. | При выключении отправка идёт через `UnreliableSequenced`: старые пакеты отбрасываются, потеря ничего не блокирует. При включении используется `ReliableOrdered`. |

Пороги отправки (на стороне владельца):

| Опция | По умолчанию | Значение |
|---|---|---|
| Position Threshold | 0.001 | Смещение меньше этой дистанции не отправляется. Действует и на масштаб. |
| Rotation Threshold | 0.1 | Поворот меньше этого угла в градусах не отправляется |

Приём (на остальных клиентах):

| Опция | По умолчанию | Значение |
|---|---|---|
| Interpolation Delay | 0 | Сколько секунд отставать от настоящего. `0` означает автоматический расчёт, см. ниже. |
| Extrapolate | выкл. | Если новее снимка нет, продолжать движение по последней скорости |
| Max Extrapolation Time | 0.25 | Наибольшая длительность экстраполяции в секундах |
| Teleport Distance | 0 | Если разрыв между текущей и целевой позицией больше этого значения, объект переходит в целевую позицию, а буфер очищается. `0` отключает проверку. |

Удалённые клиенты хранят буфер снимков с отметками времени и показывают объект в момент `ServerTime - delay`, смешивая два снимка вокруг этого момента. Снимки старше последнего отбрасываются. После смены владельца буфер очищается.

Автоматическая задержка равна двум интервалам отправки состояния. Интервал считается из `Send Rate`, `Serialization Rate` и частоты тика сервера так же, как объект реально отправляется ([тики и время](ticks-and-time.md#how-ticks-drive-sending)). При настройках по умолчанию (`Send Rate` 20, `Serialization Rate` 0, тик сервера 30 Гц) объект уходит раз в 2 тика, и задержка получается около 0.13 с. Задавайте `Interpolation Delay` вручную, только если нужен другой баланс между плавностью и отставанием.

## NetworkRigidbody

Синхронизирует `Rigidbody` и требует его на том же объекте. Всегда использует доставку `UnreliableSequenced`.

| Опция | По умолчанию | Значение |
|---|---|---|
| Sync Velocity | вкл. | Дополнительно отправлять линейную и угловую скорость, что улучшает экстраполяцию |
| Interpolation Delay | 0 | Сколько секунд отставать от настоящего. `0` означает автоматический расчёт, те же два интервала отправки, что у `NetworkTransform`. |
| Teleport Distance | 5 | Разрыв больше этого значения переносит тело в целевую позицию. `0` отключает проверку. |

У владельца тело ведёт себя обычным образом. У остальных клиентов NetPulse делает его кинематическим (предварительно обнулив скорость) и двигает через `MovePosition` и `MoveRotation` в `FixedUpdate`, экстраполируя до четверти секунды, если снимки запаздывают. При смене владельца новый владелец получает обратно значение `Is Kinematic`, которое было у префаба, а прежний владелец становится кинематическим. Если игроки должны уметь подбирать и бросать объект, сочетайте компонент с режимом [владения](ownership.md) `Takeover` или `Request`.

Для движения объекта используйте либо `NetworkTransform`, либо `NetworkRigidbody`, но не оба сразу.

## NetworkAnimator

Синхронизирует параметры `Animator`, чтобы удалённые копии проигрывали те же переходы.

| Опция | По умолчанию | Значение |
|---|---|---|
| Animator | авто | Синхронизируемый `Animator`. Если поле пусто, берётся компонент на том же GameObject. |
| Sync Layer Weights | выкл. | Дополнительно синхронизировать веса слоёв начиная с первого |

- Параметры `bool`, `int` и `float` передаются потоком вместе с состоянием объекта. Владелец читает их, остальные выставляют.
- Триггеры в поток не входят. Вызывайте `networkAnimator.SetTrigger("Attack")` у владельца. Он запускает триггер локально и отправляет RPC, который запускает его у остальных клиентов. Вызовы не от владельца игнорируются. `ResetTrigger` действует только локально.
- Список параметров читается из контроллера в `Awake`, поэтому назначьте контроллер до создания объекта.

```csharp
using NetPulse;
using UnityEngine;

public sealed class AttackAnimation : MonoBehaviour
{
    [SerializeField] private NetworkAnimator _networkAnimator;
    [SerializeField] private Animator _animator;

    public void Attack(float speed)
    {
        _animator.SetFloat("Speed", speed);
        _networkAnimator.SetTrigger("Attack");
    }
}
```

## Свои компоненты

Для других случаев напишите `NetworkBehaviour` с `SyncVar<T>` или `OnSerialize` ([синхронизация состояния](state-sync.md)). Три компонента выше написаны как обычные скрипты такого вида, а код `NetworkTransform` послужит хорошей отправной точкой для собственного интерполятора.
