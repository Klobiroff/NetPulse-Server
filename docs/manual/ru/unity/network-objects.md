# Сетевые объекты

Сетевой объект: GameObject, который существует у каждого клиента комнаты и везде имеет одну и ту же идентичность. Его собирают из компонента `NetworkObject` и ваших скриптов `NetworkBehaviour`. На этой странице описаны создание, уничтожение и поиск объектов. Состояние, RPC и владение вынесены на отдельные страницы.

## Подготовка префаба

1. Добавьте `NetworkObject` на корень префаба.
2. Добавьте свои скрипты `NetworkBehaviour` и компоненты вроде `NetworkTransform` на корень или на его потомков.
3. Сохраните префаб в `Assets`. NetPulse сам добавит его в `NetworkPrefabRegistry`.

В инспекторе `NetworkObject` есть такие настройки:

| Настройка | Значение |
|---|---|
| Ownership Mode | `Fixed`, `Takeover` или `Request` ([владение](ownership.md)) |
| Interest Group | События этого объекта получают только игроки, подписанные на группу; `0` означает всех ([низкоуровневый API](low-level-api.md#interest-groups)) |
| Persist Across Scenes | Сохранять объект, когда мастер загружает новую сетевую сцену ([сцены](scenes.md)). Объект должен быть корневым. |
| Scene Object / Scene Id | Для объектов, размещённых в сцене (см. ниже) |

`NetworkObject` один раз в `Awake` находит все `NetworkBehaviour` на объекте и его потомках, в том числе неактивных, и нумерует их в порядке иерархии. Этот номер идентифицирует поведение в сетевом трафике, поэтому иерархия должна быть одинаковой на всех клиентах, а добавлять `NetworkBehaviour` к сетевому объекту во время работы нельзя. На одном объекте может быть до 256 поведений.

## Реестр префабов

При создании объекта передаётся небольшой числовой идентификатор, а не имя, поэтому у всех клиентов должна быть одна и та же таблица префабов. Эта таблица называется `NetworkPrefabRegistry` и обычно лежит в `Assets/Resources/NetworkPrefabRegistry.asset`, а на неё ссылается поле `Prefab Registry` в настройках.

Реестр пересобирается автоматически при импорте, перемещении или удалении префаба в `Assets`, а также перед каждой сборкой. Идентификаторы назначаются один раз на префаб (по GUID ассета) и никогда не переиспользуются, так что таблица остаётся стабильной между сборками. Префабы вне папки `Assets`, например внутри пакетов, не учитываются. Для ручной пересборки используйте `NetPulse > Rebuild Prefab Registry` или кнопку в Project Settings и в Hub.

Идентификаторы берутся из реестра, поэтому клиентские и серверные сборки, которые общаются между собой, нужно собирать из одного и того же состояния проекта. Ошибка «Received spawn for unknown prefab id» означает, что у другой стороны есть префаб, которого нет у вас.

## Instantiate и Destroy

```csharp
using NetPulse;
using UnityEngine;

public sealed class Spawner : MonoBehaviour
{
    [SerializeField] private GameObject _playerPrefab;

    private GameObject _player;

    private async void Start()
    {
        await Pulse.Connect();
        await Pulse.JoinOrCreateRoom("arena");
        _player = Pulse.Instantiate(_playerPrefab, new Vector3(0f, 1f, 0f), Quaternion.identity, Color.red);
    }

    private void OnDestroy()
    {
        if (_player != null)
        {
            Pulse.Destroy(_player);
        }
    }
}
```

`Pulse.Instantiate(prefab, position, rotation, data, interestGroup)` сразу создаёт объект на вашем клиенте, делает вас его владельцем и просит остальных создать его у себя. Сервер кэширует создание, поэтому игроки, вошедшие позже, тоже его получают. Метод возвращает новый `GameObject`, либо `null` с сообщением об ошибке в логе, если вы не в комнате (офлайн-режим считается комнатой), префаба нет в реестре или на корне префаба нет `NetworkObject`.

Необязательный аргумент `data` едет вместе с созданием. Каждый клиент читает его из `NetworkObject.InstantiationData` сразу, как только объект появился; так удобно передавать цвет, команду или seed. Это может быть всё, что понимает динамический сериализатор: числа, `string`, `Guid`, массивы, `PropertyTable` и типы Unity `Vector2`, `Vector3`, `Quaternion`, `Color`, `Vector2Int` и `Vector3Int`.

```csharp
using NetPulse;
using UnityEngine;

public sealed class Tinted : NetworkBehaviour
{
    [SerializeField] private Renderer _renderer;

    public override void OnNetworkSpawned()
    {
        if (NetworkObject.InstantiationData is Color color)
        {
            _renderer.material.color = color;
        }
    }
}
```

Аргумент `interestGroup` относится к самому событию создания: объект создают только игроки, подписанные на эту группу. Дальнейший трафик объекта (состояние, RPC) использует `Interest Group`, заданную в инспекторе его `NetworkObject`, поэтому задайте обоим одинаковое значение.

Есть и перегрузка `Pulse.Instantiate(string prefabName, ...)`, которая ищет префаб в реестре по имени. Чтобы она работала надёжно, имена должны быть уникальными.

`Pulse.Destroy(gameObject)`, `Pulse.Destroy(networkObject)` и `networkObject.Destroy()` удаляют объект у всех клиентов и убирают его кэшированные события из комнаты. Делать это могут только владелец или мастер-клиент; остальные получают предупреждение, и ничего не происходит.

- Обычный `Object.Destroy(gameObject)` для сетевого объекта удаляет его только на вашем клиенте. У остальных копия остаётся.
- Сценовые объекты по сети уничтожить нельзя. `Pulse.Destroy` для такого объекта уничтожает лишь вашу локальную копию.
- Когда игрок выходит из комнаты, объекты, которыми он владел в этот момент, уничтожаются у всех клиентов. Объекты, которые он уже передал другому, остаются. Игрок, который лишь неактивен, сохраняет свои объекты.
- Когда вы сами выходите из комнаты или теряете соединение, все несценовые сетевые объекты локально уничтожаются.

## Что сообщает NetworkObject

| Член | Значение |
|---|---|
| `ViewId` | Идентификатор в пределах комнаты ([основные понятия](../concepts.md#network-objects-and-viewid)) |
| `IsSpawned` | Зарегистрирован и живёт в комнате |
| `IsMine`, `Owner`, `OwnerActorId` | Кто владелец. `IsMine` истинно и тогда, когда вы не в комнате. |
| `OwnershipMode` | Режим, заданный в инспекторе |
| `InstantiationData`, `PrefabId` | Что пришло вместе с созданием |
| `IsSceneObject`, `SceneId` | Сведения о сценовом объекте |
| `InterestGroup`, `PersistAcrossScenes` | Настройки инспектора |
| `Behaviours` | Поведения `NetworkBehaviour` на нём |

Внутри `NetworkBehaviour` напрямую доступны `NetworkObject`, `IsMine`, `Owner`, `ViewId` и `IsSpawned`. `Pulse.FindObject(viewId)` возвращает объект с таким идентификатором или `null`.

## Сценовые объекты {#scene-objects}

Сетевыми можно сделать и объекты, которые стоят в сцене с самого начала: дверь, предмет, общий куб. Включите `Scene Object` на `NetworkObject`. Инспектор назначит следующий свободный `Scene Id` (от 1 до 999) и будет использовать его как view id объекта. `Scene Id` должны быть уникальны в пределах сцены; дубликат переназначается при сохранении, с предупреждением.

Сценовые объекты ведут себя немного иначе:

- Они не создаются по сети. У каждого клиента своя копия из загруженной сцены, а копии находят друг друга по view id.
- Они принадлежат мастер-клиенту. Мастер сообщает о них серверу вместе с режимами владения после входа и снова после того, как становится мастером. Сценовый объект, который кто-то забрал и затем вышел, возвращается мастеру.
- Их нельзя уничтожить по сети, и они не могут сохраняться между сценами.
- Когда мастер загружает новую сетевую сцену, сценовые объекты старой сцены исчезают, а объекты новой сцены регистрируются после загрузки ([сцены](scenes.md)).

## Сохранение между сценами

Корневой сетевой объект с включённой опцией `Persist Across Scenes` переживает `Pulse.LoadScene`. NetPulse вызывает для него `DontDestroyOnLoad` и сообщает серверу, что его нужно сохранить. Все остальные несценовые сетевые объекты локально уничтожаются, когда начинается загрузка сетевой сцены, а сервер их забывает. См. [сцены](scenes.md).
