# RPC

Удалённый вызов процедуры (RPC) запускает метод сетевого объекта на других клиентах. Пометьте метод атрибутом `[NetRpc]` и вызывайте его через сгенерированное свойство `Rpc`. Компилятор проверяет аргументы, а поиска по имени во время работы нет.

## Объявление и вызов

```csharp
using NetPulse;
using NetPulse.Common;
using UnityEngine;

public sealed partial class Hero : NetworkBehaviour
{
    [NetRpc(RpcTarget.Others)]
    private void Hit(int damage, Vector3 at, NetRpcInfo info) => Debug.Log($"{info.Sender?.NickName} hit for {damage} at {at}");

    [NetRpc(RpcTarget.MasterClient, Delivery = DeliveryMode.Unreliable, OwnerOnly = true)]
    private void Report(string text) => Debug.Log(text);

    public void Attack(Player victim)
    {
        Rpc.Hit(10, transform.position);
        Rpc.To(RpcTarget.All).Hit(10, transform.position);
        Rpc.To(victim).Report("attacked");
    }
}
```

- `Rpc.Hit(10, position)` отправляет вызов получателям, указанным в атрибуте.
- `Rpc.To(RpcTarget.All).Hit(...)` заменяет получателей для одного вызова.
- `Rpc.To(player).Report(...)` отправляет вызов одному игроку.

Атрибут выглядит так: `[NetRpc(RpcTarget target = RpcTarget.All, Delivery = ..., OwnerOnly = ...)]`. Без аргументов получатели `All`, а доставка `ReliableOrdered`.

Требования:

- Класс наследует `NetworkBehaviour` и объявлен `partial`. Подойдёт и `sealed partial`, тогда сгенерированное свойство `Rpc` остаётся приватным. В незапечатанном классе свойство `protected`: подклассы могут им пользоваться, внешний код нет. Для внешних вызовов добавьте публичный метод вроде `Attack` выше.
- Метод возвращает `void`, не имеет параметров `ref`, `out` и `in`, не статический, не обобщённый, не абстрактный, а его имя не повторяется в классе. Перегрузки RPC запрещены, потому что идентификатор RPC вычисляется как хеш имени метода.
- Параметр `NetRpcInfo` необязателен и должен стоять последним. Его заполняет получатель, в вызов он не входит.
- Уровень доступа метода может быть любым.

Анализатор сообщает о нарушениях как об ошибках компиляции; см. [анализаторы](analyzers.md) (NP0001 до NP0005).

## Типы параметров

RPC принимает те же типы, что и [сообщение](messages.md#serializable-types): `bool`, `byte`, `sbyte`, `short`, `ushort`, `int`, `uint`, `long`, `ulong`, `float`, `double`, `char`, `string`, `Guid`, перечисления, векторы Unity, `Quaternion`, цвета и `Rect`, `Player`, `NetworkObject`, типы `[NetSerializable]` и `INetMessage`, а также массивы и `List<T>` из них. Для всего остального передавайте поля отдельными параметрами или пометьте тип атрибутом `[NetSerializable]`.

## Получатели

| `RpcTarget` | Где выполняется |
|---|---|
| `All` | У каждого клиента, включая вызывающего. Копия вызывающего выполняется сразу, внутри вызова. |
| `Others` | У каждого клиента, кроме вызывающего |
| `MasterClient` | У мастера. Если вызывает мастер, выполняется локально. |
| `Owner` | У владельца объекта. Если вызывает владелец, выполняется локально. Для сценового объекта без явного владельца владельцем считается мастер. |
| `AllBuffered` | Как `All`, и сервер ещё сохраняет вызов и проигрывает его клиентам, которые войдут позже |
| `OthersBuffered` | Как `Others`, с тем же сохранением |

`Rpc.To(player)` отправляет вызов одному игроку. Если это вы, вызов выполняется локально.

Буферизованные RPC привязаны к объекту. Сервер удаляет сохранённые вызовы объекта, когда объект уничтожается, поэтому опоздавший игрок не получает RPC объекта, которого уже нет. Буферизацию используйте для состояния, которое новичкам нужно нагнать, например «дверь открыта». Если же значение просто последнее по времени, предпочтите [`SyncVar`](state-sync.md) или свойство, потому что буферизованный вызов проигрывается столько раз, сколько он был сделан.

## Доставка

`Delivery` выбирает режим транспорта: `ReliableOrdered` (по умолчанию), `ReliableUnordered`, `UnreliableSequenced` или `Unreliable`. Ненадёжный RPC может потеряться, поэтому применяйте его только для повторяющихся одноразовых вызовов вроде косметических эффектов.

## NetRpcInfo и OwnerOnly

Завершающий параметр `NetRpcInfo` даёт получателю три значения:

| Член | Значение |
|---|---|
| `Sender` | `Player`, который вызвал. `null`, если он уже вышел. |
| `SenderActorId` | Номер актора отправителя |
| `ServerTime` | Серверное время на этом клиенте в момент выполнения вызова |

`OwnerOnly = true` заставляет вызывающий клиент отказаться от вызова, если он не владеет объектом: пишется предупреждение, и ничего не отправляется. Проверка выполняется только у вызывающего. Получатели не проверяют, что отправитель владеет объектом, поэтому изменённый клиент всё равно может отправить вызов. Для важных действий проверяйте отправителя на стороне получателя по `info.Sender` или `info.SenderActorId`, либо на сервере плагином.

```csharp
using NetPulse;
using UnityEngine;

public sealed partial class Door : NetworkBehaviour
{
    [NetRpc(RpcTarget.MasterClient)]
    private void RequestOpen(NetRpcInfo info)
    {
        if (info.Sender == null)
        {
            return;
        }

        Rpc.To(RpcTarget.AllBuffered).SetOpen(true);
    }

    [NetRpc(RpcTarget.All)]
    private void SetOpen(bool open) => transform.localRotation = Quaternion.Euler(0f, open ? 90f : 0f, 0f);

    public void Use() => Rpc.RequestOpen();
}
```

## Когда можно вызывать

Объект должен быть создан в сети, а клиент должен находиться в комнате. Иначе вызов пишет ошибку в лог и ничего не делает. Вызывайте RPC из `OnNetworkSpawned` или позже, а не из `Awake` или `OnEnable` ([жизненный цикл](lifecycle.md)).

Полученные RPC выполняются в главном потоке. Если у получателя объекта ещё нет, вызов там отбрасывается. События, которые приходят во время загрузки сетевой сцены, удерживаются и затем проигрываются по порядку ([сцены](scenes.md)).

## Вызовы в старом стиле

Прежний API, `CallRpc("Name", target, args)`, по-прежнему работает с методами `[NetRpc]`, но использует рефлексию и строковые имена. Он описан в разделе [низкоуровневый API](low-level-api.md#reflection-rpcs), а анализатор (NP0011) предлагает вместо него сгенерированный вызов.
