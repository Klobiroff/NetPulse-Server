# Сцены

Сетевые сцены держат всех игроков комнаты в одной сцене Unity. Мастер-клиент вызывает `Pulse.LoadScene`, и каждый клиент, в том числе вошедший позже, загружает ту же сцену. События, которые приходят во время загрузки, удерживаются и затем проигрываются по порядку.

```csharp
using NetPulse;
using UnityEngine;

public sealed class ArenaFlow : NetPulseCallbacks
{
    [SerializeField] private GameObject _propPrefab;

    public async void StartArena()
    {
        if (!Pulse.IsMasterClient)
        {
            return;
        }

        try
        {
            await Pulse.LoadScene("Arena");
        }
        catch (NetPulseException e)
        {
            Debug.LogError($"Could not load: {e.Message}");
        }
    }

    public override void OnNetworkSceneLoaded(string sceneName)
    {
        Debug.Log($"Scene ready: {sceneName}");

        if (Pulse.IsMasterClient)
        {
            Pulse.Instantiate(_propPrefab, Vector3.zero, Quaternion.identity);
        }
    }
}
```

Добавьте каждую загружаемую сцену в `File > Build Settings`. Если сцену не удалось загрузить, в лог пишется ошибка, а операция загрузки завершается ошибкой `InvalidState`.

## Загрузка

`Pulse.LoadScene(string sceneName)` и `Pulse.LoadScene(int buildIndex)` работают так:

- Вызывать их может только мастер-клиент. Любой другой получает предупреждение и операцию, завершившуюся ошибкой `Forbidden`. Вне комнаты они завершаются ошибкой `InvalidState`. Чтобы дать другим игрокам возможность запустить загрузку, отправьте мастеру сообщение или RPC, а `LoadScene` вызовет он.
- Мастер записывает свойство комнаты `_scene` со значением `"{loadId}:{nameOrIndex}"`. `loadId` растёт с каждой загрузкой, поэтому клиенты отличают новый запрос от уже обработанного. Сами клиенты записать это свойство не могут.
- Каждый клиент, включая мастера, загружает сцену асинхронно через `SceneManager.LoadSceneAsync` в одиночном режиме.
- Возвращаемая операция на мастере завершается после загрузки сцены. На остальных клиентах сигналом служит `OnNetworkSceneLoaded`.

Если вторая `LoadScene` стартует, пока не закончилась первая, побеждает более новая загрузка, а операция старого вызова завершается ошибкой `NetPulseReturnCode.Cancelled`. Так же завершается загрузка, во время которой клиент вышел из комнаты или отключился. `await` такой операции выбрасывает `NetPulseException`.

## Автосинхронизация

Опция `Auto Sync Scene` в настройках (по умолчанию включена, [настройки и редактор](settings-and-editor.md)) включает саму загрузку. Когда она выключена, `Pulse.LoadScene` только записывает свойство `_scene` и сразу завершается, а сцену автоматически никто не загружает. Этот режим подходит играм, которые сами управляют сценами и хотят лишь общее значение «текущая сцена».

## Опоздавшие игроки

Когда игрок входит в комнату, клиент читает `_scene`. Если комната уже в другой сцене, клиент её загружает. Если активная сцена совпадает, ничего не происходит, и `OnNetworkSceneLoaded` для этого игрока не поднимается, поэтому не опирайтесь на этот колбэк в настройке, нужной каждому игроку. Объекты, созданные в сцене, приходят из кэша сервера как обычно.

Совпадение определяется по имени сцены или по индексу сборки, в той форме, которую использовал мастер.

## Что происходит с объектами

Когда загрузка начинается, у каждого клиента:

- Сетевые объекты, которые не являются сценовыми и не имеют `Persist Across Scenes`, локально уничтожаются. Сервер их забывает и удаляет их кэшированные события.
- Объекты с `Persist Across Scenes` (корневые, помеченные `DontDestroyOnLoad`) остаются и сохраняют владельца.
- Сценовые объекты старой сцены исчезают вместе с ней. После загрузки объекты новой сцены регистрируются, а мастер заново регистрирует их на сервере.

## Очередь событий

С момента начала загрузки и до её конца события комнаты накапливаются в очереди: RPC, обновления состояния, типизированные сообщения, события `RaiseEvent`, создание и уничтожение объектов. Когда сцена готова, сценовые объекты регистрируются, очередь проигрывается в исходном порядке, и затем поднимается `OnNetworkSceneLoaded(sceneName)`. Благодаря этому ни один RPC и ни одно создание объекта не попадает в объект, которого ещё нет.

Изменения свойств, входы и выходы игроков, события владения и смены мастера в очередь не попадают. В очереди помещается до 4096 событий. Сверх этого самые новые события отбрасываются, а в лог пишется предупреждение. Если вы выходите из комнаты или отключаетесь во время загрузки, очередь сбрасывается.

## Колбэки

`Pulse.Events.OnNetworkSceneLoaded` передаёт имя загруженной сцены. Подкласс `NetPulseCallbacks` может переопределить `OnNetworkSceneLoaded`, а класс, реализующий `ISceneCallbacks`, может зарегистрироваться через `Pulse.AddCallbackTarget`.

Пример Basic показывает этот процесс на двух сценах и паре кнопок, доступных только мастеру, которые их загружают. У его префаба игрока включён `Persist Across Scenes`, поэтому игроки остаются при смене сцены.
