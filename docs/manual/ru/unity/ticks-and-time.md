# Тики и время

У всех клиентов комнаты есть общее представление о времени. Эталоном служат серверные часы, а каждый клиент хранит их оценку. Поверх этих часов сервер определяет частоту тиков, и это даёт цикл с фиксированным шагом, который идёт одинаково у всех.

## Серверное время

`Pulse.ServerTime` содержит оценку серверных часов в секундах типа `double`. Два клиента, которые прочитали его в один момент, получат значения, различающиеся только на ошибку оценки, поэтому оно подходит как база времени для всего, что должно совпадать: обратных отсчётов, интерполяции, перезарядок, стартующих от общего события.

Как идёт оценка: при подключении рукопожатие даёт первое смещение. Дальше клиент каждые две секунды отправляет пинг, берёт время кругового пробега каждого ответа, хранит последние восемь замеров и использует смещение того замера, у которого круговой пробег наименьший. `Pulse.RoundTripTimeMs` показывает круговой пробег транспорта. До подключения значение ничего не значит, а в [офлайн-режиме](offline-mode.md) оно следует за локальными часами.

Общий обратный отсчёт занимает несколько строк: мастер сохраняет время старта в свойстве комнаты, и каждый клиент считает остаток по одним и тем же часам.

```csharp
using NetPulse;
using UnityEngine;

public sealed class Countdown : MonoBehaviour
{
    private static readonly RoomKey<double> StartAt = new("startAt");

    public void Begin(float seconds) => Pulse.CurrentRoom.Set(StartAt, Pulse.ServerTime + seconds);

    private void Update()
    {
        var room = Pulse.CurrentRoom;
        if (room == null || !room.Properties.ContainsKey(StartAt.Name))
        {
            return;
        }

        var remaining = room.Get(StartAt) - Pulse.ServerTime;
        if (remaining > 0d)
        {
            Debug.Log($"Starting in {remaining:F1} s");
        }
    }
}
```

Для всего, что вы сравниваете между клиентами, используйте `ServerTime`, а не `Time.time`. Значение `NetRpcInfo.ServerTime` это серверное время на принимающем клиенте в момент выполнения RPC, а не момент отправки. Чтобы измерить время в пути, положите `Pulse.ServerTime` в данные сообщения или RPC.

## Тики

Когда вы входите в комнату, сервер объявляет частоту тиков (30 в секунду, если сервер не настроен иначе). До этого и в офлайн-режиме клиент использует 30.

| Член | Значение |
|---|---|
| `Pulse.TickRate` | Тиков в секунду |
| `Pulse.Tick` | Номер текущего тика, `floor(ServerTime * TickRate)`, типа `long` |
| `Pulse.TickDelta` | Длина одного тика в секундах, `1 / TickRate` |

Поскольку номер вычисляется по общим часам, все клиенты согласны, какой тик сейчас текущий.

## OnNetworkTick

Переопределите `OnNetworkTick(long tick)` в `NetworkBehaviour`, чтобы выполнять код раз в тик. Метод вызывается для каждого созданного в сети объекта, ваш он или чужой, поэтому перед обработкой ввода проверяйте `IsMine`.

```csharp
using NetPulse;
using UnityEngine;

public sealed class TickMover : NetworkBehaviour
{
    [SerializeField, Min(0f)] private float _speed = 5f;

    private Vector3 _direction;

    public void SetDirection(Vector3 direction) => _direction = direction;

    public override void OnNetworkTick(long tick)
    {
        if (IsMine)
        {
            transform.position += _direction * (_speed * (float)Pulse.TickDelta);
        }
    }
}
```

Что гарантируется:

- `OnNetworkSpawned` выполняется раньше первого `OnNetworkTick` объекта ([жизненный цикл](lifecycle.md)).
- Тики запускаются раннером NetPulse в `Update`, раньше вашего собственного `Update`.
- Если кадр длился дольше одного тика, цикл нагоняет, но за кадр выполняется не больше 5 тиков. Если приложение зависло больше чем на секунду, более старые тики пропускаются и выполняются только последние 5.
- Первый кадр после входа в комнату лишь запоминает начальный тик. Первый `OnNetworkTick` приходит в одном из следующих кадров.
- Исключение в одном `OnNetworkTick` попадает в лог и не останавливает остальные объекты.

## Как тики управляют отправкой {#how-ticks-drive-sending}

Состояние объекта отправляется на границах тиков, сразу после вызовов `OnNetworkTick` этого тика, поэтому изменение, сделанное в тике, уходит в том же тике. Отправка идёт не на каждом тике. Число тиков между отправками определяют две настройки ([настройки и редактор](settings-and-editor.md)):

```text
rate = max(1, min(SendRate, SerializationRate))
ticksPerSend = max(1, round(TickRate / rate))
```

`SerializationRate`, равный `0`, в этой формуле означает частоту тиков.

| Частота тиков | Send Rate | Serialization Rate | Отправки |
|---|---|---|---|
| 30 | 20 (по умолчанию) | 0 (по умолчанию) | Каждый 2-й тик, 15 в секунду |
| 30 | 30 | 0 | Каждый тик |
| 30 | 10 | 0 | Каждый 3-й тик, 10 в секунду |
| 30 | 60 | 15 | Каждый 2-й тик |

Частота одинакова для всех объектов. Когда игрок входит, владельцы на следующем тике отправляют полное состояние независимо от расписания.

## Интерполяция и время

Чужие объекты показываются чуть в прошлом, чтобы всегда было два снимка для смешивания. `NetworkTransform` рисует объект в момент `ServerTime` минус задержка. Каждый снимок несёт серверное время отправки владельца; при собственном `OnSerialize` оно доступно как `NetStream.Timestamp`. Настройка задержки описана на странице [компоненты](components.md).
