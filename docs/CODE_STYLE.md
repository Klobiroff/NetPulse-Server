# NetPulse — C# code style (обязателен для всего кода: сервер, Common, плагины, Unity-пакет, тесты, сэмплы)

## Дизайн
- SOLID, одна ответственность на класс, зависимости через интерфейсы (конструктор; в Unity — `[SerializeField] private` или `Construct`/`Init`), композиция вместо наследования, маленькие интерфейсы.
- Состояние инкапсулировано: поля `private` (в Unity `[SerializeField] private`). Наружу — свойства (`get` или `{ get; private set; }`), коллекции как `IReadOnlyList<T>` / `IReadOnlyCollection<T>`.
- `readonly`, `sealed`, `static`, `const` везде, где возможно. Классы по умолчанию `sealed`, если не задуманы для наследования (например, `RoomPlugin` и `NetworkBehaviour` — не sealed).
- Современный синтаксис, где он делает код короче и понятнее: expression-bodied члены, pattern matching (`is`, `is not`, `switch`-выражения), `??`, `??=`, `?.`, `Changed?.Invoke()`, интерполяция, `nameof`, кортежи и деконструкция, инициализаторы коллекций, `using`-объявления.
- Тернарный оператор — для простого выбора из двух значений. Вложенные тернарники запрещены.
- Короткие методы, guard clauses вместо глубокой вложенности.

## Null safety
- Аргументы проверяются: `_x = x ?? throw new ArgumentNullException(nameof(x));`. В net10-проектах можно `ArgumentNullException.ThrowIfNull(x);`.
- Опциональные значения: `?.`, `??`, `??=`, `is null` / `is not null`.
- **Unity:** для всего, что наследуется от `UnityEngine.Object`, — только `== null` / `!= null` / `if (obj)`; никогда `?.`, `??`, `??=`, `is null`. Вместо `GetComponent` + проверки — `TryGetComponent`.

## Форматирование
- Allman: фигурные скобки всегда на новой строке (namespace, типы, методы, свойства с телом, if/for/while/…), даже у однострочного `if`.
- Метод, свойство или конструктор с телом из одного выражения пишется в одну строку через `=>`.

## Переменные
- Локальные переменные всегда объявляются через `var`, в том числе `var x = new Foo();`.
- Во всех остальных местах, где тип известен из контекста, используется target-typed `new()`: поля, свойства, аргументы, `return`.

## Массивы
- Пустой массив: `Array.Empty<T>()`, никогда `new T[0]`.
- Массив в переменной: `var a = new int[] { 0, 1, 2 };` (в одну строку, если короткий).
- Массив, переданный аргументом: `new[]`, каждый элемент на своей строке, скобки — на отдельных строках.

## Именование
| Член | Формат |
|---|---|
| private-поле | `_camelCase` |
| public-поле / свойство | `PascalCase` |
| static-поле (любой доступ) | `PascalCase` |
| константа (любой доступ) | `PascalCase` |
| локальная переменная / параметр | `camelCase` |
| метод, класс, интерфейс | `PascalCase`, интерфейсы с префиксом `I` |

Вместо публичных полей — свойства. Исключение: DTO-структуры протокола из SPEC §3 (`OperationRequest` и т.д.) переводятся на свойства `{ get; set; }` с теми же именами — для вызывающего кода это совместимо.

## Комментарии
- **Никаких комментариев и XML-doc (`///`)**: код объясняет себя именами и структурой. Это отменяет прежнее требование «XML docs на публичном API».
- Разрешены только `// TODO: …` — коротко и конкретно, ровно там, где осталась незаконченная работа.
- Сторонний вендорный код (LiteNetLib) не трогаем.

## Unity
- Ссылки на объекты из инспектора и настраиваемые значения — `[SerializeField] private` (+ `[Min]`, `[Range]`, `[Header]` по необходимости).
- Компоненты кэшируются в `Awake`; никаких `Find` / `GetComponent` в `Update`.

## Ограничения C# 9 / netstandard2.1 (NetPulse.Common и весь Unity-пакет)
- `record` и `init` запрещены (нет `IsExternalInit` в Unity 2021). Вместо `ThrowIfNull` — `?? throw` или явный `if`.
- Target-typed `new()`, `is not`, `switch`-выражения и `static`-лямбды — разрешены (это C# 9).
- В серверных net10-проектах (не Common) `record` можно использовать для неизменяемых данных.

## Финальная проверка каждого файла
Скобки на новых строках, однострочники через `=>`, `var` для всех локальных переменных, `new()` в остальных местах, `Array.Empty`, именование по таблице, null-проверки (с правилом `== null` для Unity), `[SerializeField] private`, никаких комментариев, кроме TODO.
